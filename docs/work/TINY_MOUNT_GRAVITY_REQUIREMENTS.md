# Tiny Mount arbitrary-gravity requirements

Status: **TEMPORARY execution requirements — DELETE ON SUCCESS**.

Purpose: move gravity-aware Tiny Mount behavior out of Clinging: Reoriented and into Scale Brews without coupling Scale to Clinging or contaminating the entity-collision solver. The work must remain independently mergeable to Scale `main` and later be reconciled with the in-progress `chatgpt-editing` gravity-frame architecture.

## 1. Functional requirements

- **TGR-001 Native ownership.** Scale Brews owns Tiny Mount behavior under arbitrary cardinal gravity. Clinging must not be required for bee flight, chicken glide, wolf pounce/landing or equivalent Tiny Mount mechanics to respect a non-DOWN frame.
- **TGR-002 Subsystem boundary.** Tiny Mount gravity support belongs to Scale's mount/integration layer, not the entity-collision solver. Tiny Mounts and anatomical support remain distinct systems.
- **TGR-003 Effective root frame.** Tiny Mount control/forces must be interpreted using the effective gravity frame of the root mount when an external gravity provider is available.
- **TGR-004 DOWN equivalence.** With DOWN/vanilla gravity, behavior must remain observably equivalent to current Scale behavior.
- **TGR-005 New impulses only.** Changing gravity does not rotate existing world-space momentum retroactively. Only newly generated mount control vectors/impulses are transformed from local mount/gravity coordinates into world coordinates.
- **TGR-006 Bee/look-directed flight.** New flight velocity generated by Tiny Mounts must express rider-intended yaw/pitch in the root mount's gravity frame while preserving existing speed/max-pitch/max-vertical-speed policy.
- **TGR-007 Chicken glide.** Chicken glide damping and its jump-held/released behavior must act along local gravity vertical, not hardcoded world Y, for all six cardinal frames.
- **TGR-008 Wolf pounce.** Wolf pounce launch and landing cleanup must act in the root wolf's gravity frame while preserving attack/cooldown/damage semantics.
- **TGR-009 Mixed rider/root frames.** Mount mechanics use the root mount's physical frame, not the rider's frame merely because the rider supplies controls.
- **TGR-010 Frame changes mid-action.** A frame change between control samples affects subsequent generated impulses deterministically and must not double-transform or reinterpret already applied movement.
- **TGR-011 Optional gravity provider.** Scale must remain fully loadable and functional without Gravity Changer. Absence of an external provider yields the vanilla/DOWN frame.
- **TGR-012 Gravity Changer integration.** When Gravity Changer is present, Scale provides/installs an optional reusable adapter that reads effective entity gravity without requiring Clinging. Gravity Changer must not become a required dependency.
- **TGR-013 Single authority.** Scale has one canonical gravity-frame provider service. `collision` and `mount` may consume it, but they must not maintain separate registries/readers that can disagree.
- **TGR-014 Provider ownership.** Installing a second different provider owner fails explicitly; repeating installation by the same owner is idempotent, preserving the intent of entity-collision FR-073.
- **TGR-015 Native capability marker.** Scale must expose a stable, cheap way for optional consumers such as Clinging to detect that native gravity-aware Tiny Mount handling is present, so legacy compatibility mixins can stand aside and avoid double handling.
- **TGR-016 Compatibility with current Clinging.** The native path must match or supersede the behavior currently supplied by Clinging's `ScaleFlightGravityMixin`, `ScaleWolfGravityMixin` and `ScaleChickenGravityMixin`, but those mixins are regression references, not implementation specifications.
- **TGR-017 No collision dependency.** Native Tiny Mount gravity support must not require the new entity-collision subsystem to be READY/active. It may share a transversal gravity-frame service but not contact/carry/anatomy lifecycle.
- **TGR-018 Future chatgpt-editing reconciliation.** When `main` changes are incorporated into `chatgpt-editing`, the collision branch must adopt/delegate to the same canonical gravity-frame service rather than retain `collision.internal.GravityFrames` as a competing authority.
- **TGR-019 Consumer-safe API.** Any public capability used by Clinging to detect native Tiny Mount support must be versioned/stable enough not to require reflection over private implementation details.
- **TGR-020 Documentation truth.** After successful implementation/merge, permanent Scale docs must describe gravity-aware Tiny Mount behavior and optional Gravity Changer integration without claiming entity-collision G7 completion.

## 2. Non-functional requirements

- **TNFR-001 No hard dependency.** Base build/runtime without Gravity Changer remains valid.
- **TNFR-002 Deterministic transforms.** Six-frame transformations use one tested conversion path; no per-mob duplicated coordinate formulas where a shared helper is sufficient.
- **TNFR-003 Bounded compatibility logic.** Optional-mod detection occurs at initialization/cached boundaries, not repeated reflective discovery in hot movement loops.
- **TNFR-004 No double application.** Native Scale and legacy Clinging compatibility cannot both transform the same impulse/event.
- **TNFR-005 Reviewable migration.** Changes are split by service boundary, mechanic migration and docs/compatibility. No force-push/history rewrite.
- **TNFR-006 Main-safe independence.** The work must be implementable/validatable from Scale `main` without depending on unstable `chatgpt-editing` internals.

## 3. Acceptance outline

Adversarial regression coverage must include all six frames, DOWN equivalence, rider/root frame disagreement, frame change between actions, no provider present, native provider present and a double-application guard with a Clinging compatibility fixture or equivalent capability-level test.
